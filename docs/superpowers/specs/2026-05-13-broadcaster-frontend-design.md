## 0. Purpose

Build the first vertical slice of the Live Athan Flutter app: the **broadcaster-side** experience, end to end, against mock data. This proves the app shell, theming, routing, role-based entry, repository contracts, and the live-broadcast UX loop are sound — before any backend integration begins.

The slice ships when:

- A user can sign in as a mock Muadhin, land on Home, navigate to Dashboard, tap "Slide to Broadcast", pass a Pre-Live Check, go live (with a real microphone-driven ambient meter), end the broadcast, see a Summary, and return to Dashboard.
- The mock data layer is isolated to two folders (`lib/data/mock/`, `lib/data/repositories/mock/`) and a single Riverpod override block — backend swap-in is a one-day change.
- All five broadcaster screens are golden-tested and `flutter analyze` is clean.

## 1. Decisions snapshot

Captured during brainstorming (see prior conversation transcript for the question-by-question rationale):

| # | Decision | Reason |
|---|---|---|
| D1 | **Scope: 5 broadcaster screens** — Home, Dashboard, Go-Live Pre-Check, Live Broadcast, Broadcast Summary | Smallest set that proves the live-Athan loop end-to-end |
| D2 | **Mock data via repository pattern with synchronous in-memory fixtures** | Easiest to read, easiest to swap; loading states are not the value being proved this sprint |
| D3 | **Sign-in screen with mock-user tiles + role-based redirect on entry.** Muadhin and Admin both land on `/broadcaster/home`; Listener lands on `/listener/home` stub | Demonstrates the eventual auth flow shape; lets us preview Muadhin vs Listener experiences without a real backend. Admin gets the Muadhin view in v1 because there is no Admin UI yet — full admin dashboard is `BUILD_PLAN.md` M6 |
| D4 | **Live Broadcast = visual-only simulation + real microphone ambient meter** | Adds tangible realism without bringing Chime SDK or audio licensing concerns into this slice |
| D5 | **Broadcast Summary screen in scope (5 screens total, not 4)** | Natural closer to the broadcast loop; without it the user has no feedback for the broadcast they just ended |
| D6 | **Feature-module layout: single `lib/features/broadcaster/` module** | Role-shaped, not RFQ-shaped — mirrors how this slice was scoped. Symmetrical `listener/` peer arrives later |
| D7 | **Riverpod for state management, go_router for routing** | Already committed in `BUILD_PLAN.md` §M0 |
| D8 | **Dark theme only in v1, RTL pipeline wired but no Arabic strings** | Matches prototype, defers polish; the architecture supports both when we commit translation work |
| D9 | **No real audio playback or transmission** | Out of scope until M4 (Chime SDK module per `BUILD_PLAN.md`) |

| S5 | Broadcast Summary | `/broadcaster/summary/:streamId` | `prototype/screens/broadcast-summary-masjid-al-abrar.html` |

**Supporting screens (not in the 5 but required for the slice to function):**

- Sign-in screen (mock-user tile picker)
- Stub Listener home (so role-based redirect has a destination)
- Stub Nearby / Inbox / Me tabs (so the bottom nav renders correctly)

**Cross-cutting:**

- App shell (`MaterialApp.router`), theme tokens, locale wiring
- go_router config with auth-gate redirect + role-based entry redirect
- Riverpod provider tree with mock-repository overrides
- Mock data layer: fixtures + repository contracts + mock implementations
- Bottom-nav shell (5 tabs) wrapping `/broadcaster/home` and `/broadcaster/dashboard`
- Microphone permission flow (Pre-Live Check)
- Real microphone ambient-level meter on Live Broadcast (`noise_meter`)

### 2.2 Out of scope (explicitly deferred)

- Listener-side experience beyond the stub home — listener prayer widget, Nearby Masjids, masjid detail, live player, etc.
- Schedule Broadcast (`schedule-broadcast-muadhin.html`) and Audit Log (`audit-log-muadhin.html`) screens
- Real audio publishing, real WebRTC, AWS Chime SDK — `BUILD_PLAN.md` M4
- Firebase Auth, Firestore, FCM, Storage — `BUILD_PLAN.md` M1 / M2
- Light theme and full Arabic localization (RTL plumbing only)
- Empty-state, loading-skeleton, offline-mode UIs
- Smart TV targets (`BUILD_PLAN.md` D3 deferred them)
- Web target hardening (the slice will run on web; `noise_meter` falls back to a sine-wave fake)

### 2.3 Out of scope deliberately, but the architecture must not block it

When the next sprint or backend integration arrives, none of these should require a refactor:

- Swapping `MockMasjidRepository` → `FirebaseMasjidRepository` (and similar): single Riverpod override change.
- Adding loading states: repository contracts will be promoted to `Future<...>` returns — UI consumers will already use Riverpod's `AsyncValue` because we route through providers.
- Adding the listener variant of Home: drop a peer module under `lib/features/listener/` mirroring `broadcaster/`.
- Adding more bottom-nav destinations: replace the `StubScreen` with the real one.

### 3.2 Mock-data isolation contract

Two non-negotiable rules:

1. **`lib/data/mock/*.dart` is imported only by `lib/data/repositories/mock/*.dart`.** Nothing else in the app touches the fixtures directly. A lint rule or a CI grep enforces this if it becomes a recurring violation.
2. **Repository instantiation happens in exactly one place** — `main.dart`, inside `ProviderScope(overrides: [...])`. To swap to backend: replace the override values.

**Concrete swap-out procedure (when backend lands):**

```dart
// Before (v1, this spec)
ProviderScope(
  overrides: [
    authRepositoryProvider.overrideWithValue(MockAuthRepository()),
    masjidRepositoryProvider.overrideWithValue(MockMasjidRepository()),
    broadcastRepositoryProvider.overrideWithValue(MockBroadcastRepository()),
    scheduleRepositoryProvider.overrideWithValue(MockScheduleRepository()),
  ],
  child: const MuslimGuiderProApp(),
)

// After (backend integration)
ProviderScope(
  overrides: [
    authRepositoryProvider.overrideWithValue(FirebaseAuthRepository(firebaseAuth)),
    masjidRepositoryProvider.overrideWithValue(FirestoreMasjidRepository(firestore)),
    broadcastRepositoryProvider.overrideWithValue(ChimeBroadcastRepository(functions)),
    scheduleRepositoryProvider.overrideWithValue(AdhanScheduleRepository()),
  ],
  child: const MuslimGuiderProApp(),
)
// Then delete lib/data/mock/ and lib/data/repositories/mock/.
```

If a repository's return type needs to change from sync to async during backend integration, only the interface and the impls change — UI code already routes through Riverpod providers which adapt either shape (`Provider`, `FutureProvider`, `StreamProvider`).

enum StreamStatus { starting, live, ended, failed }

  final String muadhinId;

  final DateTime? endedAt;

## 5. Repository contracts

All methods are synchronous in v1 (per D2). Streams used where state changes over time (`watchCurrentUser`, `watchCurrentLiveStream`).

```dart
abstract class AuthRepository {
  User? get currentUser;
  Stream<User?> watchCurrentUser();
  Future<User> signIn(String mockUserId);        // Future for the eventual real impl
  Future<void> signOut();
}

abstract class MasjidRepository {
  Masjid? findById(String id);
  List<Masjid> all();
}

abstract class BroadcastRepository {
  Stream<BroadcastStream?> watchCurrentLiveStream(String masjidId);
  List<BroadcastStream> recentBroadcasts(String masjidId, {int limit = 3});
  BroadcastStream? findById(String id);
  BroadcastStream startBroadcast({
    required String masjidId,
    required String muadhinId,
  });
  BroadcastStream endBroadcast(String streamId, EndReason reason);
}

abstract class ScheduleRepository {
  PrayerTimes forDate(DateTime date, {required String masjidId});
}
```

## 6. Routing

`go_router` config in `lib/core/router/app_router.dart`. Redirect logic reads `currentUserProvider`.

```
/                                redirect to:
                                   /sign-in              if user == null
                                   /broadcaster/home     if user.role == muadhin OR admin
                                   /listener/home        if user.role == listener

/sign-in                         SignInScreen

ShellRoute (broadcaster bottom nav, shown for Muadhin/Admin only)
  ├─ /broadcaster/home           HomePrayerWidgetMuadhinScreen
  ├─ /broadcaster/dashboard      MasjidDashboardScreen
  ├─ /broadcaster/nearby         StubScreen(label: 'Nearby')
  ├─ /broadcaster/inbox          StubScreen(label: 'Inbox')
  └─ /broadcaster/me             StubScreen(label: 'Me')

Full-screen (pushed on top, no bottom nav)
  ├─ /broadcaster/go-live                GoLivePreCheckScreen
  ├─ /broadcaster/live/:streamId         LiveBroadcastScreen
  └─ /broadcaster/summary/:streamId      BroadcastSummaryScreen

/listener/home                   StubListenerHome
```

**Auth gate:** every route except `/sign-in` redirects to `/sign-in` if `currentUserProvider` is null. The role-based redirect on `/` fires once on first build after sign-in and after sign-out.

**Live-flow nav:**

- Dashboard → tap Slide-to-Broadcast → `context.push('/broadcaster/go-live')`
- Pre-Live → tap Continue → call `broadcastRepository.startBroadcast(...)` → `context.pushReplacement('/broadcaster/live/$streamId')`
- Live → tap End Broadcast → call `broadcastRepository.endBroadcast(...)` → `context.pushReplacement('/broadcaster/summary/$streamId')`
- Summary → tap Done → `context.go('/broadcaster/dashboard')`

`pushReplacement` is used between Go-Live → Live → Summary so the back stack doesn't accumulate intermediate broadcast screens.

## 7. State management

### 7.1 Repository providers (overridden in `main.dart`)

```dart
final authRepositoryProvider      = Provider<AuthRepository>((_) => throw UnimplementedError());
final masjidRepositoryProvider    = Provider<MasjidRepository>((_) => throw UnimplementedError());
final broadcastRepositoryProvider = Provider<BroadcastRepository>((_) => throw UnimplementedError());
final scheduleRepositoryProvider  = Provider<ScheduleRepository>((_) => throw UnimplementedError());
```

Throwing in the default ensures we never silently use the wrong impl — every entry point (`main.dart`, test setup) must override explicitly.

### 7.2 Derived providers

| Provider | Type | Reads | Emits |
|---|---|---|---|
| `currentUserProvider` | `StreamProvider<User?>` | `authRepositoryProvider.watchCurrentUser()` | current `User` or `null` |
| `currentMasjidProvider` | `Provider<Masjid?>` | `currentUserProvider`, `masjidRepositoryProvider` | Muadhin's `Masjid` or `null` |
| `prayerTimesProvider` | `Provider.family<PrayerTimes, DateTime>` | `scheduleRepositoryProvider`, `currentMasjidProvider` | computed times |
| `liveStreamProvider` | `StreamProvider.family<BroadcastStream?, String>` | `broadcastRepositoryProvider.watchCurrentLiveStream(masjidId)` | active stream or null |
| `recentBroadcastsProvider` | `Provider.family<List<BroadcastStream>, String>` | `broadcastRepositoryProvider.recentBroadcasts(...)` | 3 most-recent |
| `micLevelProvider` | `StreamProvider<double>` | `noise_meter` package (mobile), sine fallback (web/desktop) | 0..1 normalized |

### 7.3 Screen-local controllers (StateNotifier)

| Controller | State | Scope |
|---|---|---|
| `SignInController` | `selectedMockUserId`, `busy` | SignInScreen |
| `GoLivePreCheckController` | `{ mic, network, geofence } → enum CheckStatus { idle, checking, ok, failed }` | GoLivePreCheckScreen |
| `LiveBroadcastController` | elapsed ticker + fake listener-count random walk | LiveBroadcastScreen |

### 7.4 Microphone meter

- **Package:** `noise_meter` (^5.0.0), with `permission_handler` (^11.3.1) for the mic permission.
- **Provider:** `micLevelProvider` is a `StreamProvider<double>` that:
  - On mobile: subscribes to `NoiseMeter().noiseStream`, maps `meanDecibel` linearly into `0.0 .. 1.0` (clamp at -60 dB → 0, 0 dB → 1).
  - On web/desktop: emits a sine-wave fake with period ~3 s so the meter still animates during demos.
- **Lifecycle:** the provider is `autoDispose`. Subscription starts when the first listener (LiveBroadcastScreen) attaches; cancels when the screen disposes.
- **Permission:** `GoLivePreCheckScreen` triggers the request via `permission_handler`. If denied, the "Continue" button stays disabled with an inline "Permission required" card.
- **No transmission, no recording.** The mic feed is read only for meter visualization.

## 9. Screen specifications

Each screen below: purpose, prototype reference, key widgets, providers consumed, navigation in/out.

### 9.1 Sign-In Screen — `/sign-in`

- **Purpose:** Pick a mock user to sign in as. Demonstrates the eventual auth flow shape and drives role-based redirect.
- **Layout:** Centered Muslim Guider logo + headline "Choose a profile". Below: vertical list of `MockUserTile`s — avatar, display name, role badge, masjid name (if Muadhin). Tap fires `signInController.selectUser(id)` which calls `authRepository.signIn(id)`.
- **State:** `SignInController(StateNotifier)` holds `selectedUserId`, `busy`. On `busy == true`, tiles are non-interactive and a spinner overlays the selected tile.
- **Navigation out:** on success, router's redirect logic moves us to `/broadcaster/home` (Muadhin/Admin) or `/listener/home` (Listener).

### 9.2 Home — Prayer Widget (Muadhin) — `/broadcaster/home`

- **Prototype:** `home-prayer-widget-muadhin.html` (313 lines).
- **Top bar:** MUADHIN role badge (top-left, cell_tower icon), idle mic-lock indicator (top-right).
- **Header:** time HH:mm in gold display, dual-line date (English Gregorian + Hijri via `hijri` package).

- **Prototype:** `masjid-dashboard-muadhin.html` (after the cleanup commits).

## 11. Error handling

| Failure | Behavior |
|---|---|
| Mic permission denied (Pre-Live) | "Permission required" card with "Open Settings" button (deep link via `permission_handler`); Continue button stays disabled |
| Mic unavailable at runtime (Live) | Meter idles at minimum; `debugPrint` only; screen functions otherwise |
| Bad `streamId` in `/broadcaster/live/:id` or `/broadcaster/summary/:id` | Router redirects to `/broadcaster/dashboard` and shows a snackbar "Stream not found" |
| Sign-in fails (unknown user id) | SignInController surfaces an inline error under the tile; tile becomes interactive again |
| Repository throws (any mock impl) | Caught by feature controllers; user-facing snackbar with the message; logged via `debugPrint` |
| `flutter_test` golden mismatch in CI | Reports diff in PR comment; require explicit re-baseline |

Loading skeletons and empty-state UIs are deliberately not designed in v1 — mock data fixtures guarantee non-empty happy paths.

## 13. Testing strategy

### 13.1 Coverage targets

| Layer | Target | Type |
|---|---|---|
| `lib/data/models/` | 90% | unit |
| `lib/data/repositories/` (interfaces + mock impls) | 90% | unit |
| `lib/providers/` | 80% | unit (ProviderContainer with mock overrides) |
| `lib/features/` | 70% | widget tests |
| Whole project minimum | 70% | `flutter analyze` zero issues, `flutter test --coverage` |

### 13.2 Test types

- **Model unit tests** — construction, equality, `copyWith`, computed getters (e.g., `BroadcastStream.duration`, `PrayerTimes.next`).
- **Repository unit tests** — each mock method returns the expected fixture; `startBroadcast` mutates state correctly; `watchCurrentLiveStream` emits when a stream starts/ends.
- **Provider tests** — override repos with stubs, verify `currentMasjidProvider` is non-null when user is Muadhin, null otherwise; `prayerTimesProvider` reads from schedule repo; `micLevelProvider` emits sine-wave fake on test (since no mic on test runner).
- **Widget tests** — each screen renders happy-path without throwing under a mock `ProviderScope.overrides`.
- **Golden tests** — the 5 broadcaster screens rendered at `780×1812` (matches prototype frames). Stored under `test/goldens/`. CI fails on diff.
- **Integration test** — `integration_test/broadcaster_happy_path_test.dart`: launch app → sign in as Imam Yusuf → land on Home → tap Dashboard → tap Slide-to-Broadcast → swipe → land on Pre-Live → wait for checks → Continue → land on Live → wait 3 s → End Broadcast → confirm → land on Summary → Done → back on Dashboard.

## 14. Risks & mitigations

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | `noise_meter` package doesn't behave consistently across Android versions / iOS audio session conflicts | Medium | Low | Wrap in a try/catch and fall back to a sine-wave fake — meter still animates so screen never looks broken |
| R2 | `hijri` package's Gregorian-to-Hijri mapping disagrees with prototype's hardcoded date | Low | Low | Pin the package to a tested version; display "approximate" tooltip on Hijri label if discrepancy >1 day |
| R3 | Porting the AnalogClock's CustomPainter cosmic-centerpiece is fiddly | Medium | Medium | Reuse the original `analog_clock_painter.dart` mostly verbatim; isolate paint code to one widget; widget tests catch regressions |
| R4 | The slide-to-broadcast widget (no off-the-shelf package matches the prototype's gold pill exactly) | Medium | Low | Build it bespoke as a Stateful widget driven by `GestureDetector.onHorizontalDragUpdate`; ~150 LOC, unit-testable |
| R5 | Mock-data isolation drifts over time (someone imports `lib/data/mock/` from a feature) | Medium | Medium | Linter rule or pre-commit grep; called out in `CLAUDE.md` / README |
| R6 | Repository interfaces become sync-only and need to flip to async when backend lands → cascade UI changes | Low | Medium | All UI reads through Riverpod providers; flipping a `Provider` to `FutureProvider` is a one-liner per provider |
| R7 | Web target degrades visibly without mic and with reduced fonts | Low | Low | Documented limitation; sine-wave fallback for mic; google_fonts handles web fine |

## 16. Acceptance criteria

- [ ] The 5 broadcaster screens render without error on Android and iOS simulators.
- [ ] The sign-in screen lists at least 3 mock users with distinct roles.

- [ ] `flutter analyze` reports zero issues.
- [ ] `flutter test --coverage` passes, ≥70% line coverage.
